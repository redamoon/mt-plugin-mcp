# 記事を作る

下書きで作り、確認してから公開する流れです。公開時の再構築は **`rebuild_entry`** です。サイト全体の `rebuild_site` は使いません。

ツールの引数は [tools.md](../tools.md) の記事ツールを参照してください。

## AI にこう頼む

```
テストブログに「オンボーディング確認」という記事を下書きで作って。
本文は短い挨拶でよい。まだ公開しないで。
```

公開まで任せる場合:

```
さっきの下書きを確認して問題なければ公開して。
再構築は記事単位にして。サイト全体は触らないで。
```

既存記事を直す場合:

```
ブログ一覧から対象サイトを選び、「オンボーディング」を含む記事を探して。
該当の本文を直して下書きのまま保存して。
```

## 実際に呼ばれるツール

```
blog_list
  → blog_id を確認
entry_preview（任意）
  → 公開ファイルは書かずに見た目を確認
entry_create(..., status="draft")
  → 既定も下書き。この時点ではサイトに出ない
```

確認して公開するとき:

```
entry_get または entry_list
  → 対象 ID を確認
entry_update(..., status="publish")
rebuild_entry
  → 個別アーカイブと依存インデックス
```

既存を探すときは `entry_list` の `keyword` と `offset` を使います。本文が必要なら `entry_get` です。

## チェックポイント

- 下書きだけなら、管理画面の記事一覧に下書きがある。公開 URL はまだ無い（または古い静的ファイルのまま）。
- 公開＋`rebuild_entry` のあと、個別ページが更新されている。

## 注意

- 削除（`entry_delete`）は取り消せません。消す前に `entry_get` で対象を確認させてください。
- `category_ids` には記事カテゴリだけを渡します。コンテンツタイプ用のカテゴリセット内 ID は使いません（[tools.md](../tools.md#権限と注意)）。
- 画像を本文に入れる場合は [画像を記事に貼る](attach-image.md) です。
